# WaveBench v0.8.28 发布说明

本版本承接 `v0.8.27`，主要更新为示波器观察与建议、uv 环境及插件管理，以及版本身份和发行物验证。安装方式见[安装说明](https://github.com/Scaxlibur/WaveBench/blob/v0.8.28/docs/getting-started/installation.md)，实际发行状态以 [GitHub Release](https://github.com/Scaxlibur/WaveBench/releases/tag/v0.8.28) 为准。

## 示波器观察与建议

新增 `scope observe`，默认查询身份、可用状态和输入耦合，不读取波形。HTTP MCP 新增 `doctor.config`、`scope.observe` 和 `scope.advise`，支持结构化仪器检查、示波器观察以及显示／时基建议。建议基于可用测量和显式期望频率，不自动执行；缺少证据时返回不可用原因。

`scope observe --fetch-waveform` 显式生成波形报告，并可通过 `--expect` 校验逐通道期望。验收汇总区分失败、部分可用、不可用和跳过，避免把查询失败或不完整结果判断为通过。

波形报告在同一受控会话和独占资源租约内完成高阻确认及读取。访问、能力和参数预检失败时拒绝采集；不确定 I/O 后停止剩余通道，不自动重连继续操作。观察路径还限制 factory 构造阶段的 Core transport I/O。

显式波形读取可能停止采集、启用通道、修改传输设置并消费错误队列，不恢复原运行状态。依次读取多个通道不证明同次采集，报告不会据此计算需要同步证据的相位、相关性、延迟和交点。MCP 不开放波形读取路径。具体用法与副作用见 [CLI Reference](https://github.com/Scaxlibur/WaveBench/blob/v0.8.28/docs/reference/cli.md)和 [MCP 指南](https://github.com/Scaxlibur/WaveBench/blob/v0.8.28/docs/how-to/serve-mcp.md)。

## uv 环境与插件管理

开发环境使用 `uv.lock` 固定依赖，通过 `uv sync --locked` 准备环境，通过 `uv run --no-sync` 执行命令。CI 也使用锁定环境，保留 Linux／Windows 的 Python 3.11／3.12 检查。

受管插件的本地安装与源码构建改用 uv，目标虚拟环境不再要求 pip。插件安装仍只处理指定本地包，不自动下载依赖；源码构建使用环境中预装的 build backend。uv 必须在 PATH 中可用。

旧 pip 安装记录继续参与健康检查、回滚和恢复。开发环境与仪器运行环境应分开：默认 `uv sync` 会清理未声明的插件，专用运行环境通过 `uv pip install` 更新 Core，并在更新后检查插件状态。迁移步骤见[管理仪器插件](https://github.com/Scaxlibur/WaveBench/blob/v0.8.28/docs/how-to/manage-plugins.md)。

## 版本身份与发布检查

- `wavebench --version` 和 `python -m wavebench --version` 返回已安装发行包的版本。运行时不再向上搜索 `pyproject.toml`；缺少发行元数据时显示 `0+unknown`。
- 插件 descriptor 与安装包兼容范围统一按 PEP 440 判断，保留开发版与正式版的先后关系，拒绝未达到最低正式版本的预发布包。
- `Dev` 直接推送触发 CI，相关文档变更触发文档检查。
- CI 构建源码包和 wheel，并在仓库外的独立环境中安装 wheel 及其声明依赖，验证版本、命令入口、模板和离线 plan 检查。
- tag 工作流校验 tag、项目版本、锁文件、发行物 metadata 和发布说明；源码、文档和发行物检查全部通过后，使用已验证的同一份附件生成 Release 草稿，最终发布由维护者审核完成。

安装文档区分发行包、固定 tag 源码和开发线。无硬件快速开始使用包内模板，不依赖源码仓库中的示例文件。

## 其它修复与开发接口

修复 Windows 上分析结果文件原子替换遇到短暂占用时直接失败的问题，使用既有的有限重试策略，保持原子写入与失败报告。

增加供 Core 内部使用的有界 run 输入快照绑定：显式选择来源，限制条目与总字节数，并检测读取过程中的身份或内容变化。Advisor 插件、外部模型执行及授权流程仍属于 RFC 范围；本版本不提供完整的 advisor 运行时。

## 升级注意事项

1. 安装或升级 Core 后，先执行 `--version` 和依赖检查，再检查已安装插件。包版本修改后，editable 环境须重新同步元数据。
2. 需要受管插件操作时安装 uv；已有 pip 安装的插件不要求全部重装。降回依赖 pip 的旧 Core 时，目标环境仍需提供 pip。
3. 自定义插件应核对 metadata 与 descriptor 的版本范围。预发布 Core 不能冒充对应正式版本；无安装元数据的源码树可能无法通过插件兼容检查。
4. `scope observe` 的默认查询与 `--fetch-waveform` 的状态修改边界不同。调用方应显式选择，并检查验收状态，不能只看进程退出码。
5. 仪器插件独立发行。Core 更新不提高外置插件的型号覆盖或实机验证等级；本次观察与建议的回归使用 fake transport 和合成信号。
